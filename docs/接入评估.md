# 开源项目与接入评估

核对时间：2026-09-28。本表区分“项目已经实现的功能”和“丫丫状态当前已接入的功能”；当前只有 Codex 接入。

| 对象 | 可参考的开源项目 | 实际采用的入口 | 对丫丫状态的意义 |
| --- | --- | --- | --- |
| Codex、WorkBuddy、CodeBuddy、Codeg | [Agent Companion](https://github.com/changexbc/agent-companion) | Hook / Webhook；WorkBuddy 还用本机日志补充沙箱审批 | WorkBuddy 的任务状态与指定会话跳转已有实作，可以参考事件结构；CodeBuddy 的跳转有时只能打开工程。 |
| WorkBuddy | [workbuddy-buddy](https://github.com/FlashFamily/workbuddy-buddy) | WorkBuddy 插件 Hook → 本地事件文件 → 状态机 | 已实现思考、工作、等待、完成和失败等状态；适合参考低内容读取的事件格式。它是独立宠物应用，不是多工作台集合。 |
| Codex、Claude Code、ZCode | [LLM Pulse](https://github.com/zuuzii-org/llm-pulse) | 本地任务数据库与事件文件，可选 Hook | 参考“本地读取 + Hook 增强”和状态可信度设计；ZCode 适配仅针对作者本机布局。 |
| Codex、Claude Code | [CodeStatus](https://github.com/henriquegpb/codestatus) | 生命周期 Hook；进程仅用于发现和会话退出判断 | 参考等待审批、等待回答、未知状态的状态机，以及点击回原终端/工作区。 |
| Kimi CLI、Gemini CLI、Cursor Agent、OpenCode 等 | [tmux-scout](https://github.com/qeesung/tmux-scout) | 各工具 Hook / OpenCode 插件 | 覆盖的工具种类多，但它是终端任务监听，不等于 Kimi Work 桌面版可直接接入。 |
| 豆包工作 DoubaoWork | [doubao-cli](https://github.com/Fullstop000/doubao-cli) | 本机 CDP 与客户端内部接口 | 可查询单轮任务状态并打开指定会话；依赖未公开协议。本机客户端版本 2.31.8 尚未验证兼容；启用 CDP 可能重启应用。 |
| Kimi Work | [Nowledge Kimi Work Connector](https://github.com/nowledge-co/community) | Kimi Work 内嵌 Kimi Code 运行时与本地会话导入 | 说明桌面版存在可读的本地会话，但该项目的目标是知识/会话导入，不是实时状态悬浮监控。 |
| Cursor、Copilot、Gemini、Claude、Codex、OpenCode、Windsurf | [OpenTelemetry Hooks](https://github.com/o11y-dev/opentelemetry-hooks) | 将各工具 Hook 归一成事件 | 可参考统一事件格式；它输出遥测数据，不直接提供桌面悬浮任务板。 |
| Grok Bot 宿主 | [grokbot-sdk](https://github.com/Adam91holt/grokbot-sdk) | 宿主网关与 `sand-data` 文件 | 属于实验性宿主接入，需要宿主地址和令牌；不能直接证明本机安装的 Grok Bot 客户端可读取所有云端任务状态。 |

## 建议顺序

1. **WorkBuddy**：先基于 Hook 读取真实运行/结束事件，再补只读本机会话数据用于重启恢复，验证指定对话跳转。
2. **豆包工作**：在用户不需要保留当前运行任务时验证 `doubao-cli` 与本机版本的兼容性；仅在接口稳定后接入。不要为探测擅自重启客户端。
3. **Kimi Work**：核对内嵌运行时事件与会话数据库能否合成可信状态，再验证单会话跳转。
4. **Grok Bot**：先保留应用入口。其任务在云端运行，需找到稳定的任务事件或接口后再报告逐任务状态；Grok Build 的 Hook 属于另一产品。

## 状态规则

- **任务 ID**：使用 `来源:来源任务 ID` 去重，防止不同工作台的 ID 碰撞。
- **工作中 / 等待操作 / 已完成 / 已中断 / 报错 / 未知**：只由明确事件或可验证的状态记录决定。
- **跳转**：记录每个任务的原会话链接；只有应用主页入口时，界面必须明确说明无法精确跳转。
- **时效**：数据源断开时保留最近任务并显示连接失败，不把旧状态当作实时状态。
