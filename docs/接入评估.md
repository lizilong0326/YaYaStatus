# 开源项目与接入评估

核对时间：2026-09-28。本表区分“开源项目能力”和“丫丫状态已验证的能力”。当前悬浮框已加入 Codex、WorkBuddy、Kimi Work、豆包工作、Grok Bot、Pi Agent 和 DeepSeek 网页来源；DeepSeek 扩展尚未装入 Chrome。

| 对象 | 可参考的开源项目 | 实际采用的入口 | 对丫丫状态的意义 |
| --- | --- | --- | --- |
| Codex、WorkBuddy、CodeBuddy、Codeg | [Agent Companion](https://github.com/changexbc/agent-companion) | Hook / Webhook；WorkBuddy 还用本机日志补充沙箱审批 | WorkBuddy 的任务状态与指定会话跳转已有实作，可以参考事件结构；CodeBuddy 的跳转有时只能打开工程。 |
| WorkBuddy | [workbuddy-buddy](https://github.com/FlashFamily/workbuddy-buddy) | WorkBuddy 插件 Hook → 本地事件文件 → 状态机 | 已实现思考、工作、等待、完成和失败等状态；适合参考低内容读取的事件格式。它是独立宠物应用，不是多工作台集合。 |
| Codex、Claude Code、ZCode | [LLM Pulse](https://github.com/zuuzii-org/llm-pulse) | 本地任务数据库与事件文件，可选 Hook | 参考“本地读取 + Hook 增强”和状态可信度设计；ZCode 适配仅针对作者本机布局。 |
| Codex、Claude Code | [CodeStatus](https://github.com/henriquegpb/codestatus) | 生命周期 Hook；进程仅用于发现和会话退出判断 | 参考等待审批、等待回答、未知状态的状态机，以及点击回原终端/工作区。 |
| Kimi CLI、Gemini CLI、Cursor Agent、OpenCode 等 | [tmux-scout](https://github.com/qeesung/tmux-scout) | 各工具 Hook / OpenCode 插件 | 覆盖的工具种类多，但它是终端任务监听，不等于 Kimi Work 桌面版可直接接入。 |

| Kimi Work | [Nowledge Kimi Work Connector](https://github.com/nowledge-co/community) | Kimi Work 内嵌 Kimi Code 运行时与本地会话导入 | 说明桌面版存在可读的本地会话，但该项目的目标是知识/会话导入，不是实时状态悬浮监控。 |

| Grok Bot 宿主 | [grokbot-sdk](https://github.com/Adam91holt/grokbot-sdk) | 宿主网关与 `sand-data` 文件 | 属于实验性宿主接入，需要宿主地址和令牌；不能直接证明本机安装的 Grok Bot 客户端可读取所有云端任务状态。 |

| Pi Agent | [Pi Session File Format](https://pi.dev/docs/latest/session-format)、[Extensions](https://pi.dev/docs/latest/extensions) | 本地 JSONL 会话 + `agent_start` / `agent_settled` 扩展事件 | 已读取本机最近 10 个会话；扩展已装入本机目录，当前仍运行的 Pi 进程未重载，因此实时事件尚待下一次运行验证。点击可打开 VS Code 工作区，不能定位原终端。 |
| DeepSeek 网页 | [Chrome Native Messaging](https://developer.chrome.com/docs/extensions/develop/concepts/native-messaging) | 指定域名的内容脚本 → 本机 Native Messaging → 状态文件 | 扩展与本机桥接代码已备好，空闲网页确认有独立会话链接；未装入 Chrome，未验证真实生成控件，因此不报告“工作中”。 |

## 建议顺序

1. **WorkBuddy**：已完成只读会话读取、Hook 配置及指定会话跳转验证；待下一次真实任务验证 Hook 回调。
2. **Kimi Work**：已完成只读会话与运行时结束事件解析；任务点击目前只打开应用。深链 `kimi-work://chat/<conversation_key>` 实测只回到首页，因此不标成精确跳转。
3. **豆包工作**：用户同意后已重启并开启 CDP。修正 `Default` 配置档识别、会话快照排序与重复记录合并后，列表读取到 20 个会话，最新一轮状态查询得到“已完成”，指定会话深链已验证。状态查询逐条更新列表；继续观察真实运行中/等待输入任务的状态刷新。
4. **Grok Bot**：已接入只读 Bot 会话快照与应用入口，统一显示“状态未知”。需找到稳定的云端任务事件或接口后再报告逐轮状态；Grok Build 的 Hook 属于另一产品。
5. **Pi Agent**：会话文件读取与扩展安装已完成。当前 VS Code 中的 Pi 进程继续运行；执行一次 `/reload` 或下次启动后，才能核对真实任务事件是否到达。
6. **DeepSeek 网页**：扩展、Native Messaging 主机和悬浮框读取器已完成代码与模拟消息验证。Chrome 装入扩展需要页面权限，之后再用真实生成过程校准“正在生成”信号。关闭标签后显示为离线，不推断云端状态。

## 状态规则

- **任务 ID**：使用 `来源:来源任务 ID` 去重，防止不同工作台的 ID 碰撞。
- **工作中 / 等待操作 / 已完成 / 已结束 / 已中断 / 报错 / 未知**：只由明确事件或可验证的状态记录决定；网页的“已结束”不区分自然完成与用户中止。
- **跳转**：记录每个任务的原会话链接；只有应用主页入口时，界面必须明确说明无法精确跳转。
- **时效**：数据源断开时保留最近任务并显示连接失败，不把旧状态当作实时状态。
