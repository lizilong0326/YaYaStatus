# 丫丫状态

macOS 桌面悬浮任务板。应用启动后显示在普通窗口上方，跨桌面空间保留，拖动空白处可移动位置，点击任务可跳回原工作台。

## 当前版本（0.5.2）

- 首页按更新时间合并全部来源，只显示最近 100 条任务与会话。工作台情况在齿轮设置页分成“连接中”“状态可读”“部分可用”“待接入”“读取失败”；最后一次成功读取时间保留。读取失败会在首页提示，设置按钮出现红点。“部分可用”表示会话能读到，但有些实时状态缺少证据，并非断线。
- 任务行不再显示“距最近更新多久”。工作中和等待操作显示本轮已运行时长，并每秒更新；完成、失败和中断显示本轮结束的本地日期时间。缺少可靠任务时间的条目明确显示“时间未确认”或“结束时间未记录”；Grok Bot 仅列会话，不把目录更新时间当任务时间。
- **Codex**：显示最近任务的工作中、已完成、已中断、报错或状态未知；点击任务使用 `codex://threads/<id>` 跳转。
- **WorkBuddy**：只读本机会话库，读取任务标题和保存的状态；生命周期 Hook 补充工作中、等待操作、完成及中断事件。点击已验证可进入对应会话。Hook 已合并到本机 WorkBuddy 设置，新任务触发后才能验证实际事件是否到达。
- **Kimi Work**：只读本机会话库和内嵌运行时事件记录，显示最近任务与可验证的运行/结束状态。点击可打开 Kimi 应用，目前无法精确定位到对应会话。
- **豆包工作**：内置开源 `doubao-cli` 连接器。当前本机 CDP 已开启，显示最近会话及最新一轮的运行、等待、完成、失败或取消状态；点击任务可进入指定对话。
- **Grok Bot**：只读本机的 Bot 会话快照；快照没有可信的云端任务运行/结束信号，所以条目标为“仅会话”，不再把它混同于任务状态读取失败。点击只打开 Grok Bot 应用，不能定位到指定 Bot。
- **Pi Agent（VS Code 终端）**：只读 `~/.pi/agent/sessions` 的会话文件，显示最近会话；本机 Pi 扩展记录开始、等待和最终结束事件。点击打开对应 VS Code 工作区，暂不能精确选中原终端。没有扩展事件时，仅从 Pi 已保存的最终回复识别已完成、报错和中断；中间状态显示“状态未知”。
- **DeepSeek 网页**：已准备 Chrome 扩展、本机桥接和悬浮框来源。扩展只观察已打开的 `chat.deepseek.com` 会话标签；当前尚未装入 Chrome，所以悬浮框会提示连接条件，不显示虚假的网页任务。
- 显示 Codex 的五小时和每周剩余额度（如果 Codex 服务返回这些数据）。
- 悬浮框不会因鼠标移开或切换应用而消失；关闭与重新显示入口在菜单栏。
- 保存悬浮框位置。Codex 约每 2 秒（有运行任务）或 15 秒（无运行任务）刷新。豆包工作约每 2 秒（有运行任务）或 5 秒（无运行任务）启动一次检查，另加约 1 秒/会话的实际查询时间；最近 10 个和已知活动会话优先核对。点击刷新会强制核对全部已读豆包会话。各来源的上次成功读取时间显示在设置页。
- Codex 只读访问 `app-server` 和本地 `thread_history_*.sqlite` 状态索引；WorkBuddy Hook 只保存会话 ID、状态和时间。不会将消息正文写入丫丫状态的缓存。

“状态未知”表示当前没有足够的本地状态证据。它不会被当作“已完成”。Codex 现有状态索引无法可靠区分运行中和等待用户操作；WorkBuddy 的等待状态需要真实 Hook 事件。Kimi Work 的长时间静默任务会转为“状态未知”，防止把旧记录当成实时任务。

豆包工作读取会话后、逐轮状态返回前会显示“核对中”。一次状态查询失败时，会保留短时间内验证过的状态并重试，设置页报告失败条数；超过 30 秒仍未验证的活动状态才会转为“状态未知”。来源连续读取失败超过 30 秒时，其他工作台的旧活动标记也会撤回，已确认的结束状态保持不变。未安装的来源显示“待接入”，会话格式异常或读取失败显示“读取失败”。

Codex 的会话列表本身不能区分“已完成”和“已中断”；这些状态来自本地任务索引。索引或 Codex 服务短暂读取失败时，悬浮框显示错误与上次成功读取时间，并保留最近一次确认的结果；超过 30 秒还未恢复，才把仍标为“工作中”的旧任务改为“读取中断”。已有任务时，服务意外返回空列表不会清空整个任务板，而会保留列表并重试。

时间来源：Codex 使用本轮索引的 `started_at` 和 `completed_at`；豆包工作使用最新一轮消息的创建和最终更新时间；Kimi Work 使用运行事件时间；Pi Agent 使用扩展事件或会话消息时间；WorkBuddy 新任务使用 Hook 事件，已有已完成会话使用本机会话库最后活动时间。DeepSeek 扩展在观察到开始与结束信号后记录时间，未安装或无信号时不估算。

## 运行

需要 macOS 13 或更高版本。各来源需在本机安装并登录相应工作台。

```sh
./scripts/build-app.sh
open "dist/丫丫状态.app"
```

构建出的应用在 `dist/丫丫状态.app`。若只需从源码调试，可运行 `swift build`，但建议使用 `.app` 以获得正确的应用名称和菜单栏行为。应用当前采用本机临时签名，未做 Apple 公证。

## WorkBuddy Hook

新机器上需要执行一次：

```sh
python3 scripts/install-workbuddy-hook.py
```

安装脚本会备份 `~/.workbuddy/settings.json`，再把丫丫状态的事件监听合并进去。它不会清除其他 Hook。此机器已执行安装，原设置备份在 `~/.workbuddy/settings.json.yayastatus-backup-20260928-005943`。当前 WorkBuddy 未重启，尚未用真实新任务验证 Hook 回调；悬浮框会标示“等待下一次真实事件”。

需要移除时运行 `python3 scripts/uninstall-workbuddy-hook.py`；它只移除丫丫状态的处理器，并再次备份设置。

## Pi Agent 扩展

新机器上执行一次：

```sh
python3 scripts/install-pi-extension.py
```

扩展只把会话 ID、会话文件路径、状态、进程 ID 和时间写入本机 `~/Library/Application Support/YaYaStatus/pi/sessions`，不保存提示词和回复。安装不会重启已有 Pi 进程；在 Pi 中执行 `/reload` 或下次启动后才能接收实时事件。一个会话如果没有可靠的结束事件，运行标记失去心跳后会转为“状态未知”。

## DeepSeek 网页会话

本机 Chrome 已登录 `chat.deepseek.com`，页面提供独立会话链接，因此可以跳转到具体会话。网页本身没有给丫丫状态提供本地任务事件。已写好一个仅在 `chat.deepseek.com` 运行的扩展，从当前标签读取会话 ID、侧栏标题和可见的“停止生成”控件，经 Chrome Native Messaging 写入本机状态文件。它不采集聊天正文、Cookie 或 API Key。

加载扩展需要 Chrome 授予该站点的页面访问权限。**这台机器目前还没有加载它**；以下是装入步骤：

1. 在 Chrome 打开 `chrome://extensions`，开启“开发者模式”，选择“加载已解压的扩展程序”，指定 `ChromeExtension/deepseek` 文件夹。
2. 复制 Chrome 显示的扩展 ID，运行 `python3 scripts/install-deepseek-host.py <扩展ID>` 注册本机桥接。
3. 重新加载已打开的 DeepSeek 聊天页；悬浮框会显示该标签的会话。需要用一次真实生成过程核对页面是否提供“停止生成”信号。

当前空闲页面只验证了会话链接，尚未观察到真实生成过程。扩展识别不到明确的“停止生成”控件时会显示“状态未知”；曾观察到生成、随后控件消失时显示“已结束”，不推断是自然完成还是用户中止。关闭标签后不能继续得知云端是否仍在生成。

## 后续工作台

任务展示采用 `TaskCollectionStore` + `MonitoredTask`。每个接入器需要提供来源、稳定任务 ID、标题、状态、更新时间和可选的原会话链接。能读目录却没有逐轮状态的来源要标明“仅会话”；已有任务但缺少可靠状态证据时标为“状态未知”，不能从进程存活或静默时间推断“任务已完成”。

豆包工作已在用户同意后重启，以启用本机 `127.0.0.1:9226` CDP。连接器修正了此机器的默认配置档识别，并按真实更新时间排序、合并重复快照。实测读到 20 个会话，并验证了一个会话的最新一轮状态为“已完成”。豆包会话与其他来源一起参与全局最近 100 条排序；逐轮状态优先核对最近 10 个会话，手动刷新时核对全部。它依赖本机 Node.js 22 或更高版本。如果豆包工作以后不再以 CDP 模式启动，来源会显示连接条件，不把旧的运行状态当实时状态。Grok Bot 的本地快照只能提供 Bot 目录，不能报告逐轮任务状态。

`doubao-cli` 的状态命令会通过豆包客户端读取任务树，恢复记录会保存在本机 `~/Library/Application Support/YaYaStatus/doubao-cli/turns`；其中可能包含请求内容。丫丫状态的任务列表仅保留标题、ID、状态和更新时间。

见 [开源项目与接入评估](docs/接入评估.md)。
